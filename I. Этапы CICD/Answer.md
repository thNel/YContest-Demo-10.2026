# Пояснительная записка. Этапы CI/CD

## Ответ

1. **Интеграция кода — Code Integration**
2. **Сборка проекта — Build**
3. **Запуск автоматических тестов — Run Automated Tests**
4. **Развёртывание на тестовый сервер — Deploy to Staging**
5. **Развёртывание на production-сервер — Deploy to Production**

## Условие

Нужно расположить в правильном порядке этапы:

- интеграция кода;
- сборка проекта;
- запуск автоматических тестов;
- развёртывание на тестовый сервер;
- развёртывание на production-сервер.

## Общая логика CI/CD

CI/CD автоматизирует путь изменения от попадания кода в общую кодовую базу до его развёртывания.

Упрощённая схема из предложенных вариантов:

```text
Code Integration
      ↓
Build
      ↓
Automated Tests
      ↓
Deploy to Staging
      ↓
Deploy to Production
```

## 1. Интеграция кода

Сначала изменения разработчика попадают в общий репозиторий или ветку, для которой настроен CI. Именно это событие обычно запускает pipeline.

## 2. Сборка проекта

Затем система CI должна получить из исходного кода рабочий артефакт. В зависимости от проекта это может быть компиляция, сборка frontend bundle, APK/AAB, Docker image и т. п.

## 3. Запуск автоматических тестов

После или в процессе сборки запускаются автоматические проверки: unit-тесты, integration-тесты, линтеры, статический анализ, проверки типов и другие проверки качества.

## 4. Развёртывание на тестовый сервер

Если сборка и проверки успешны, приложение разворачивается в тестовой среде — staging. Такая среда обычно максимально похожа на production.

## 5. Развёртывание на production-сервер

После прохождения предыдущих этапов версия приложения разворачивается в production и становится доступной конечным пользователям.

## Почему схема кажется неполной

В реальных проектах после `Deploy to Staging` часто действительно есть ещё один этап тестирования уже развёрнутого приложения. Это могут быть:

- smoke-тесты;
- E2E-тесты;
- acceptance-тесты;
- API-тесты;
- ручное тестирование;
- ручное подтверждение релиза.

Более реалистичная схема часто выглядит так:

```text
Code Integration
      ↓
Build
      ↓
Unit / Integration Tests
      ↓
Deploy to Staging
      ↓
Smoke / E2E / Acceptance Tests
      ↓
Deploy to Production
```

Но отдельного пункта тестирования после staging в вариантах задания нет, поэтому выбирается упрощённая пятиэтапная последовательность.
