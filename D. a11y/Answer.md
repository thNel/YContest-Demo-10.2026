# Пояснительная записка: доступность HTML-страницы

## Что требовалось сделать

В задаче дана веб-страница, которая визуально выглядит как обычный сайт с вакансиями и формой отклика, но её HTML-разметка плохо приспособлена для клавиатурной навигации и ассистивных технологий.

Основной принцип решения — не менять содержимое страницы и не перестраивать её логику, а заменить несемантические элементы на подходящие нативные HTML-элементы и правильно связать подписи с интерактивными контролами.

## Язык документа и заголовок

Язык страницы указывается на корневом элементе:

```html
<html lang="ru">
```

Это позволяет экранным дикторам выбрать правильные правила произношения.

В `<head>` также нужен `<title>`. Он используется браузером, отображается во вкладке и озвучивается ассистивными технологиями при открытии страницы.

## Семантическая структура

Безымянные контейнеры заменяются на элементы, отражающие назначение частей страницы:

- `<header>` — шапка;
- `<nav>` — навигация;
- `<main>` — основное содержимое;
- `<article>` — самостоятельная карточка вакансии;
- `<footer>` — нижняя часть страницы.

Такая разметка создаёт понятные landmarks, по которым пользователь скринридера может быстро перемещаться.

## Иерархия заголовков

Заголовки должны отражать структуру документа, а не только визуальный размер текста.

Например:

```text
h1 — название страницы
 ├─ h2 — список вакансий
 │   ├─ h3 — вакансия 1
 │   ├─ h3 — вакансия 2
 │   └─ h3 — вакансия 3
 └─ h2 — подача заявки
```

Это позволяет ассистивным технологиям построить оглавление страницы.

## Изображения

Содержательное изображение должно иметь `alt`.

Если изображение несёт информацию, `alt` кратко описывает её. Если оно декоративное, используется пустой `alt=""`, чтобы экранный диктор его пропустил.

## Навигация и действия

Переходы должны быть настоящими ссылками `<a>`, а действия — кнопками `<button>`.

`div` с `onclick` не является полноценной заменой: у него нет правильной роли, стандартной клавиатурной активации и ожидаемого поведения браузера.

Поэтому:

- переход на другую страницу или раздел — `<a href="...">`;
- открыть, закрыть, отправить — `<button>`.

## Раскрывающиеся блоки

Для блока «Подробнее» подходят `<details>` и `<summary>`.

Это нативная HTML-конструкция, которая уже поддерживает:

- клавиатуру;
- фокус;
- состояние раскрыто/закрыто;
- корректную семантику для скринридеров.

Поэтому не требуется вручную имитировать accordion через `div` и обработчики событий.

## Диалог

Модальное окно логично оформить через `<dialog>`.

Это даёт элементу специальную семантику. Кнопка закрытия также должна быть настоящим `<button>`.

## Форма

Поля отклика должны находиться внутри `<form>`.

Это объединяет связанные элементы и задаёт стандартную семантику формы.

Кнопка отправки должна быть кнопкой формы, а не произвольным кликабельным контейнером.

## Подписи полей

Текст рядом с полем сам по себе не является его подписью.

Нужно использовать `<label>`:

```html
<label for="email">Электронная почта</label>
<input id="email" type="email">
```

Теперь подпись связана с полем программно: скринридер озвучивает её вместе с контролом, а клик по подписи переводит фокус в поле.

## Группы связанных элементов

Для группы вариантов, например формата работы, используются:

```html
<fieldset>
    <legend>Предпочитаемый формат работы</legend>
    ...
</fieldset>
```

`fieldset` объединяет контролы, а `legend` сообщает название группы.

## Почему нативный HTML лучше лишнего ARIA

Если в HTML уже существует нужный элемент, его следует использовать напрямую.

Например:

```html
<button>
```

лучше, чем:

```html
<div role="button" tabindex="0">
```

Во втором случае разработчику пришлось бы самостоятельно воспроизводить поведение кнопки с клавиатуры и следить за доступностью.

Правило решения:

> Сначала корректный нативный HTML, затем ARIA только там, где нативной семантики недостаточно.

## Итог

Исправление строится вокруг восстановления правильной структуры документа:

1. `lang` и `<title>`;
2. семантические области страницы;
3. корректная иерархия заголовков;
4. ссылки для переходов;
5. кнопки для действий;
6. `<details>/<summary>` для раскрывающихся блоков;
7. `<dialog>` для модального окна;
8. `<form>` для формы;
9. `<label>` для полей;
10. `<fieldset>/<legend>` для групп;
11. `alt` для изображений.

Такой подход одновременно улучшает доступность для скринридеров, клавиатурную навигацию и общую корректность HTML.
