Тимур — фронтендер стартапа «Календарь из хаоса»: сервис собирает события из десятков источников и показывает их в
одном аккуратном календаре на неделю. Контейнер данных источники не портят: единый JSON с периодом отображения и
списком событий, у каждого — идентификатор, название и дата. О таймзонах можно забыть: все даты сравниваются как
календарные дни, строки YYYY-MM-DD. А вот время начала и конца источники пишут как попало — от «09.00», «9» и
«11.30 AM» до «90 мин» вместо длительности, опечаток вроде «1O:30» и безнадёжного «26:00» с «полуднем»; попадаются
и события, заканчивающиеся раньше своего начала, и даты вне запрошенного периода.

Помогите Тимуру: распарсите и нормализуйте время событий, отсейте невалидные записи, отрисуйте календарь —
колонки дней слева направо, вертикальная шкала времени, пересекающиеся встречи бок о бок — и приложите отчёт
о событиях, которые не удалось разобрать, с указанием причины. Дизайнер зафиксировал десктопный макет
с точностью до пикселя, используйте его.

Входные данные доступны скрипту как глобальная переменная `window.INPUT` — **уже распарсенный** JS-объект
по схеме ниже (сам JSON разбирать не нужно). Страница задаёт `window.INPUT` **до** выполнения вашего скрипта.

```json
{
    "startDate": "2026-03-16",
    "days": 3,
    "events": [
        { "id": "e1", "title": "Встреча команды", "date": "2026-03-16", "start": "9:00",  "end": "10:30" },
        { "id": "e2", "title": "Стендап",         "date": "2026-03-17", "start": "09.00", "end": "10.30" },
        { "id": "e3", "title": "Воркшоп",         "date": "2026-03-17", "start": "10:00", "duration": "90 мин" },
        { "id": "e4", "title": "Лекция",          "date": "2026-03-18", "start": "9",     "end": "11" }
    ]
}
```

- `startDate` — первый день периода отображения, строго `YYYY-MM-DD` (синтаксис гарантируется).
- `days` — целое от 1 до 7.
- `id` — уникальная строка;
- `title` — произвольная строка, в том числе длинная и со спецсимволами HTML.
- `date` — день события, тоже строго `YYYY-MM-DD`, но может лежать вне периода — такое событие невалидно. У события есть либо `start` + `end`, либо `start` + `duration` —
всегда ровно один из двух вариантов; события не переходят через полночь.

Шаблонная страница уже содержит минимальное оформление и пустой контейнер `<div id="calendar"></div>`. Скрипт строит календарь
**внутри этого контейнера** — `document.getElementById('calendar')`. Стили `body` и заголовка задаёт шаблон, менять их не нужно.
Вся вёрстка календаря и его стили — инлайн, без внешних ресурсов.

Сдаётся один файл `solution.js` — обычный браузерный скрипт (не модуль: без `module.exports`, без `require`, без
Node.js-API), без внешних зависимостей, библиотек и обращений к сети; только стандартные браузерные API. Скрипт при
выполнении обязан прочитать `window.INPUT`, построить календарь внутри `#calendar` и записать отчёт в `window.ERRORS`
(пустой массив, если невалидных событий нет).


Массив невалидных событий:

```js
window.ERRORS = [
  {"id": "e7",  "value": "26:00",      "reason": "hour-out-of-range"},
  {"id": "e9",  "value": "2026-04-01", "reason": "date-out-of-range"},
  {"id": "e12", "value": "полдень",    "reason": "unparsable"}
];
```

На каждое невалидное событие — ровно одна запись, в порядке исходного массива `events`.

- `id` — идентификатор события;
- `value` — исходное проблемное значение поля (время, длительность или дата) как оно пришло во входных данных;
- `reason` — один из пяти кодов:
  - `hour-out-of-range` — час вне 0–23;
  - `minute-out-of-range` — минуты вне 0–59;
  - `end-before-start` — конец не позже начала;
  - `date-out-of-range` — `date` вне периода;
  - `unparsable` — значение времени или длительности не соответствует ни одному формату.

### Как источники пишут время (`start`, `end`)

Основа — 24-часовая запись: час с минутами через двоеточие (`9:00`, `09:00` — с ведущим нулём или без) или через точку (`09.00`, `9.30`); самые лаконичные присылают один только час — `9`, `14`.

Зарубежный трекер пишет 12-часовую запись: час, опционально с минутами через `:` или `.`, плюс суффикс am/pm в любом регистре и пунктуации — `am`, `AM`, `a.m.`, `A.M.`, `pm`, `PM`, `p.m.`, `P.M.` — вплотную к числу или через пробел: `9am` — 09:00, `11.30 AM` — 11:30, `7.15p.m.` — 19:15.

Так же может быть три типа опечаток: буква «O»/«О» (латинская или кириллическая, в любом регистре) на месте цифры читается как `0` (`1O:30` → `10:30`); `;` читается как `:` (`14;30` → `14:30`); лишние пробелы вокруг разделителя и по краям игнорируются (`9 : 00` → `9:00`).

Диапазоны: часы 0–23, минуты 0–59. Всё, что после нормализации не подходит ни под одно из описанных написаний, разобрать невозможно.

Длительность может быть задана четырьмя способами и только ими: `N мин` (`90 мин`), `Xч Yм` (`1ч 15м`), `X ч` (`2 ч`), `Yм` (`45м`).

### Макет календаря

Календарь отрисовывается внутри контейнера `#calendar` и состоит из следующих элементов. Все размеры фиксированы и не зависят от содержимого.

#### Размеры

| Параметр | Значение |
|----------|----------|
| Вертикальный масштаб | 1 минута = 0.5 px (1 час = 30 px) |
| Высота шапки дней | 40 px |
| Ширина гаттера (левая панель с часами) | 60 px |
| Ширина колонки дня | 240 px |
| Общая высота | 40 + 24 × 30 = 760 px |
| Общая ширина | 60 + days × 240 px |
| Шрифт | `12px/1 Arial, sans-serif` |
| Горизонтальные линии сетки | `1px solid #e0e0e0` |
| Вертикальные разделители дней | `1px solid #ccc` |
| Нижняя граница шапки | `1px solid #ccc` на высоте 40 px во всю ширину |

#### Блоки событий

Каждое валидное событие отрисовывается как прямоугольный блок:

- **Позиция**: `position: absolute`.
  - `top = 40 + startMin × 0.5` px (где startMin — минуты начала от полуночи);
  - `height = (endMin - startMin) × 0.5` px;
- **Стили**:
  - `background` — цвет из палитры (см. ниже);
  - `border: 1px solid #9aa0a6`;
  - `box-sizing: border-box`;
  - `padding: 1px 4px`;
  - `overflow: hidden`;
  - `color: #3c4043`;
  - `font-size: 11px`;
  - `line-height: 1`.
- **Содержимое**: текст заголовка события (`title`), экранированный от HTML-инъекций.

#### Палитра цветов

Цвета блоков событий выбираются из фиксированной палитры по индексу события в массиве валидных событий (`index % 8`):

| # | Цвет |
|---|------|
| 0 | `#a8c7fa` |
| 1 | `#f2b8b5` |
| 2 | `#fde293` |
| 3 | `#a8dab5` |
| 4 | `#fcc7a5` |
| 5 | `#a5e3e0` |
| 6 | `#d7aefb` |
| 7 | `#d3bfb2` |

#### Раскладка колонок для пересекающихся событий

1. События внутри дня сортируются по времени начала (при равенстве — по исходному порядку).
2. Пересекающиеся события объединяются в группы: два события пересекаются, если одно начинается **до** окончания другого. Касание «впритык» (конец одного = начало другого) пересечением не считается.
3. В каждой группе событиям назначаются колонки слева направо: событию достаётся первая колонка, где оно не накладывается на предыдущее событие.
4. Колонки в группе делят ширину дня поровну: ширина = 240 / количество колонок в группе.
