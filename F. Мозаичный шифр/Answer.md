# Пояснительная записка: «Мозаичный шифр»

## Суть задачи

В первом запуске программе даётся бинарная строка `s` длины `n`. Нужно получить правильную скобочную последовательность длины не более:

```text
n + 70
```

Во втором запуске программе подаётся одна из последовательностей, ранее созданных первым запуском, и требуется восстановить исходную бинарную строку.

Порядок тестов во втором запуске может быть другим, поэтому нельзя использовать номер теста или состояние между запусками. Вся информация, необходимая для восстановления, должна находиться в самой скобочной последовательности.

## Почему простое отображение не подходит

Естественное соответствие:

```text
0 -> (
1 -> )
```

сохраняет длину и информацию, но произвольная бинарная строка при таком преобразовании не становится правильной скобочной последовательностью.

У ПСП должны выполняться два условия:

1. итоговый баланс равен нулю;
2. баланс любого префикса неотрицателен.

Значит, нужно решить две отдельные задачи:

- сделать число `0` и `1` одинаковым;
- переставить полученные скобки так, чтобы все префиксы стали допустимыми.

При этом преобразование должно быть обратимым.

## Этап 1. Приведение длины к чётной

Если исходная длина нечётная, в конец временно добавляется один `0`.

После этого рабочая длина `m` становится чётной.

Факт добавления бита сохраняется в метаданных, чтобы затем удалить его при декодировании.

Цена этого шага — максимум один дополнительный символ.

## Этап 2. Балансировка бинарной строки

Используется классическая идея балансировки по Кнуту: существует такой префикс строки, инверсия которого делает количество нулей и единиц одинаковым.

Пусть в строке длины `m` находится `w` единиц.

Необходимо получить:

```text
m / 2
```

единиц.

Рассмотрим последовательное увеличение длины инвертируемого префикса.

При длине префикса `0` единиц `w`.

Если инвертировать всю строку, единиц станет:

```text
m - w
```

При увеличении префикса на один символ количество единиц меняется ровно на единицу:

```text
0 -> 1  : +1 единица
1 -> 0  : -1 единица
```

Значения `w` и `m - w` находятся по разные стороны от `m / 2`, либо одно из них уже равно `m / 2`.

Поскольку изменение происходит шагами по единице, существует длина префикса `k`, после инверсии которой:

```text
#0 = #1 = m / 2
```

Таким образом, для балансировки достаточно сохранить только одно число `k`.

## Этап 3. Перевод в скобки

После инверсии выбранного префикса применяется:

```text
0 -> (
1 -> )
```

Нулей и единиц теперь поровну, поэтому число открывающих и закрывающих скобок одинаково.

Общий баланс равен нулю.

Однако некоторые префиксы всё ещё могут иметь отрицательный баланс. Поэтому полученная строка пока не обязательно является ПСП.

## Этап 4. Циклический сдвиг

Для полученной скобочной строки вычисляется префиксный баланс:

```text
( -> +1
) -> -1
```

Находим позицию, в которой достигается минимальное значение баланса.

Пусть строка разбита в этой точке на:

```text
A + B
```

Выполняется циклический сдвиг:

```text
B + A
```

После такого сдвига все префиксные балансы становятся неотрицательными.

Причина проста: чтение начинается с самой низкой точки исходного циклического маршрута. Поэтому все последующие значения относительно этой точки не могут уйти ниже нуля.

Общий баланс при циклическом сдвиге не меняется и остаётся нулевым.

Следовательно, после сдвига получается правильная скобочная последовательность.

Чтобы отменить преобразование, достаточно сохранить число `r` — длину перенесённого начала.

## Какие параметры нужно сохранить

После основных преобразований остаются три служебных значения:

```text
odd — добавлялся ли служебный 0;
k   — длина инвертированного префикса;
r   — величина циклического сдвига.
```

При `m` порядка `10^6` каждое из чисел `k` и `r` требует примерно 20 бит.

Служебной информации немного, но просто дописать её бинарное представление в виде скобок нельзя: произвольная последовательность `(` и `)` может нарушить корректность ПСП.

Поэтому метаданные кодируются отдельной ПСП.

## Этап 5. Упаковка метаданных в одно число

Тройка параметров упаковывается взаимно однозначно:

```text
value = (odd * (m + 1) + k) * m + r
```

Диапазоны:

```text
odd ∈ {0, 1}
k   ∈ [0, m]
r   ∈ [0, m - 1]
```

Количество возможных состояний не превышает примерно:

```text
2 * (m + 1) * m
```

Для `m ≈ 10^6` это около:

```text
2 * 10^12
```

Такое значение безопасно представляется JavaScript-типом `Number`, поскольку оно значительно меньше `Number.MAX_SAFE_INTEGER`.

## Этап 6. Кодирование метаданных ПСП фиксированной длины

Метаданные кодируются ПСП длины 50.

Количество ПСП длины `2q` равно числу Каталана:

```text
Cq = binom(2q, q) / (q + 1)
```

Для длины 50:

```text
q = 25
C25 = 4 861 946 401 452
```

Это больше максимального количества возможных значений `value`.

Следовательно, каждому набору `(odd, k, r)` можно однозначно сопоставить одну ПСП длины 50.

## Нумерация ПСП

Все ПСП длины 50 рассматриваются в лексикографическом порядке, где:

```text
( < )
```

Для построения ПСП по её номеру используется динамическое программирование.

Определяется величина:

```text
dp[remaining][balance]
```

Она показывает, сколько способов существует дописать `remaining` символов, если текущий баланс равен `balance`, чтобы в итоге получить корректную ПСП.

Переходы:

- поставить `(` и увеличить баланс;
- поставить `)`, если баланс положителен, и уменьшить его.

При построении очередного символа сначала определяется, сколько допустимых ПСП существует, если поставить `(`.

Если искомый номер меньше этого количества, ставится `(`.

Иначе весь этот блок вариантов пропускается, его размер вычитается из номера, и ставится `)`.

Обратное преобразование выполняется симметрично: при встрече `)` прибавляется количество вариантов, которые были бы лексикографически раньше при выборе `(`.

Таким образом получается взаимно однозначное соответствие:

```text
число <-> ПСП длины 50
```

## Формирование результата

После циклического сдвига основная часть `DATA` является ПСП.

Служебная часть `META` также является ПСП.

Конкатенация двух правильных скобочных последовательностей тоже является правильной скобочной последовательностью:

```text
DATA + META
```

Дополнительные контейнеры и балансирующие символы не нужны.

## Ограничение длины

Если исходная длина была чётной:

```text
|DATA| = n
|META| = 50
```

Итог:

```text
n + 50
```

Если исходная длина была нечётной, добавляется один служебный бит:

```text
n + 1 + 50 = n + 51
```

Оба варианта удовлетворяют требованию:

```text
длина <= n + 70
```

## Декодирование

Во втором запуске все действия выполняются в обратном порядке.

### 1. Разделение DATA и META

Последние 50 символов результата — это `META`.

Всё перед ними — `DATA`.

Длина `DATA` равна рабочей чётной длине `m`.

### 2. Восстановление служебного числа

По `META` вычисляется её порядковый номер `value`.

### 3. Распаковка параметров

Сначала:

```text
r = value mod m
```

Затем:

```text
x = floor(value / m)
```

Далее:

```text
k = x mod (m + 1)
odd = floor(x / (m + 1))
```

Получены все параметры первого запуска.

### 4. Отмена циклического сдвига

При кодировании первые `r` символов были перенесены в конец.

Значит, при декодировании последние `r` символов `DATA` переносятся обратно в начало.

### 5. Скобки обратно в биты

Используется обратное соответствие:

```text
( -> 0
) -> 1
```

### 6. Отмена инверсии

Первые `k` бит снова инвертируются:

```text
0 <-> 1
```

Это возвращает строку к состоянию до балансировки.

### 7. Удаление служебного нуля

Если `odd = 1`, удаляется последний добавленный `0`.

После этого полностью восстанавливается исходная бинарная строка.

## Почему порядок тестов между запусками не важен

Вся информация, необходимая для восстановления, хранится внутри каждой последовательности:

```text
DATA + META
```

Внешнее состояние не используется.

Поэтому каждый тест второго запуска декодируется независимо от остальных.

## Особенность двойного запуска

Задача использует специальный режим запуска, поэтому удобно читать вход построчно через `readline` и выдавать результат сразу после обработки очередного теста.

Это позволяет не зависеть от момента закрытия стандартного ввода и корректно работать в окружении двойного запуска.

## Сложность

Для строки длины `n`:

- подсчёт единиц — `O(n)`;
- поиск `k` — `O(n)`;
- применение инверсии — `O(n)`;
- преобразование в скобки — `O(n)`;
- поиск минимального баланса — `O(n)`;
- циклический сдвиг — `O(n)`;
- обратное восстановление — `O(n)`;
- работа с `META` — `O(1)`, так как её длина всегда 50.

Итоговая сложность:

```text
O(n)
```

на один тест и:

```text
O(Σn)
```

по всем тестам.

Память:

```text
O(n)
```

## Общая схема

Кодирование:

```text
исходная бинарная строка
        ↓
при необходимости дописать 0
        ↓
инвертировать подходящий префикс
        ↓
получить равное число 0 и 1
        ↓
0 -> (, 1 -> )
        ↓
циклический сдвиг после минимального баланса
        ↓
DATA — ПСП
        ↓
(odd, k, r) -> число -> META — ПСП длины 50
        ↓
DATA + META
```

Декодирование выполняет те же действия в обратном порядке.

Основная идея решения состоит в том, что все большие изменения исходной строки выполняются без увеличения её длины. Дополнительные символы требуются только для небольшого фиксированного блока метаданных.
